## 6. 行内效果的 GUI 补全不再多插一个「<」

**日期**：2026-11-08　**commit**：`e74c2b0`

### 动机

`[角色]<` 弹出作用对象菜单，选「仅立绘」插入 `am:` 之后，再按 Tab 选动画效果时，`ab_met` 的条目
形如 `<cross=>`（自带左尖括号），插进去会变成 `[角色]<am:<cross=>`，必须手动删掉多出来的 `<`。

### 改动点

- `core/GUI_Snippets.py`
  - 新增 snippet 组 `ab_met_inline`（中英两份）：`replace=>` / `cross=>` / `black=>` /
    `black_pass_left_minor=>` / `black_leap_down_minor=>` / `shake_in_minor=45>`，都不带左尖括号。
  - 光标位置：前五个停在 `>` 之前（接着输入时长即可），`shake_in_minor=45>` 停在 `>` 之后
    （时长已经填好），与旧 `ab_met` 的行为一致。
  - 补全分支拆分：`[角色]` + `:` → `ab_met`（整段 `<效果>`）；`[角色]<am:` + `:` → `ab_met_inline`。
  - `custom_ab_method(inline=False)`：inline 时只补 `效果=>`，不再包一层尖括号。
  - `ab_met_inline` 登记进 `init_snippets_options` 的白名单。

### 兼容性

- 旧路径（`[角色]` 直接跟效果、`<animation>` / `<bubble>` 行）行为不变，仍然走 `ab_met`。
- `custom_ab_method` 非 inline 分支生成的字符串和光标位置与改动前完全一致。

### 验证

- `py_compile` 通过；中英两份各 6 个条目全部校验「不以 `<` 开头、以 `>` 结尾、cpos 与期望一致」。
- 模拟完整交互：`[伊可]<` → 选 `am:` → 选 `black=>` → 输入 `10`，得到 `[伊可]<am:black=10>`，
  与 `RE_dialogue` 匹配成功。
- **仍未实机点过菜单**（需要图形界面）。

## 5. 对话行解析失败时给出行号与可定位的原因

**日期**：2026-11-08　**commit**：`3c00182`

### 动机

`[角色]<效果>:文本` 解析失败时，原代码只抛 `ParserError('UnableDial')`，信息里**既没有行号也没有原文**，
只说「语法错误」。而最常见的四种写法问题（全角冒号/全角尖括号、缺正文、缺冒号、角色框里有非法字符）
都只能靠肉眼猜。

### 改动点

- `core/ScriptParser.py`
  - 新增模块级 `dialogue_error_hint(text)`：只在解析失败时调用，按「角色框 → 全角符号 → 结构 → 缺正文」
    的顺序猜原因，返回中文提示。
  - 失败分支改为：先打印「第 N 行 + 原文 repr」，再打印猜测原因，最后抛出**带行号**的 `UnableDial`。
  - 全角符号检查只看「角色框右边 / 效果标签内部 / 效果标签右边」各一个字符，**不扫正文**，
    避免把中文正文里的全角标点误报成语法错误。
- `core/Exceptions.py`
  - `UnableDial` 文案加行号占位符（中英各一条）。

### 兼容性

- 只在解析失败路径上生效，正常剧本的解析结果与行为完全不变。
- 异常类型不变（仍是 `ParserError`），外层 `print(E)` + `ParErr` 的行级包装逻辑不变。

### 验证

13 条样例：3 条合法行返回空提示；全角冒号 / 全角尖括号 / 缺正文 / 缺冒号 / 角色框非法字符 / 角色框未闭合
都能给出对应提示；正文含全角标点的合法行不会误报。端到端跑一遍错误剧本，控制台输出：

```
[对话行解析失败] 第2行：'[伊可]<am:black=10>：这里用了全角冒号'
[可能的原因] 效果标签右边出现了全角符号“：”，要换成半角“:”。
[解析错误]: 无法解析为对话行（第2行），由于错误的语法！原文和可能原因已打印到控制台。
```

## 4. 行内切换效果支持指定作用对象

**日期**：2026-11-08　**commit**：`3c00182`

### 动机

原设计里，对话行的行内效果 `[人物]<效果>:文本` 只有「生效 / 不生效」两态，作用对象由全局开关
`<set:inline_method_apply>:animation|bubble|both|none` 决定：

- 默认 `both`，所以 `<cross=10>` 会**同时**让立绘和气泡交叉溶解，无法只改一个；
- 唯一的分流手段是全局 `<set:>`，它是**顺序保持的全局状态**：想让某一段只作用于立绘，就得在那段前面插一行
  `<set:inline_method_apply>:animation`、后面再插一行复位，漏写就会污染后面所有行；
- 于是「气泡硬切、立绘淡入淡出」这种最常见的需求，得靠两行设置夹住才能表达。

### 改动点

**`core/Regexs.py`**

- `RE_dialogue`：行内效果标签允许带 `对象:` 前缀（`<am:cross=10>`）。旧写法 `<cross=10>` 完全不受影响。
- 新增 `RE_method_target`：把 `<对象:效果=时长>` 拆成「前缀 / 效果名 / 时长」三段。

**`core/ScriptParser.py`**

- 新增模块级 `METHOD_TARGET_ALIAS`：`am`/`animation` → 立绘，`bb`/`bubble` → 气泡，`ab`/`both` → 两者。
- `method_parser()`：识别合法前缀，把作用对象写进返回字典的 `target` 键；**无前缀时不产生该键**，字典形状与旧版一致。
- 对话行效果决策（原 1653 行附近的 `inline_method_apply` 分支）：新增「显式目标」分支，优先级高于全局
  `inline_method_apply`。`inline_method_apply = none` 仍是全局硬开关，会禁用所有行内效果。
- `method_export()`：带 `target` 的字典会导出回 `<am:…>` 形式，保证 GUI 保存/重载不丢信息。

**`core/GUI_Snippets.py`**（编辑器补全）

- 新增 snippet 组 `ab_target`（中英两份），打完 `[角色]<` 时弹出 `am:` / `bb:` / `ab:`。
- 打完 `[角色]<am:` 之后继续弹方法列表。
- 四处 `re.fullmatch(...)` 的「效果」模板容忍 `对象:` 前缀。

### 优先级（最终语义）

1. `<set:inline_method_apply>:none` —— 全局禁用行内效果（最高）
2. 行内**显式目标** `<am:…>` / `<bb:…>` / `<ab:…>`
3. 行内无目标 + `inline_method_apply`（`animation` / `bubble` / `both`）
4. `<set:am_method_default>` / `<set:bb_method_default>` 兜底

### 用法

```rgl
<set:am_method_default>:<replace=0>
<set:bb_method_default>:<replace=0>

[伊可]<am:black=10>:只有立绘淡入淡出，气泡硬切
[伊可]<bb:black=10>:只有气泡淡入淡出
[伊可]<black=10>:两个都淡入淡出（旧写法，含义与以前一致）
```

### 兼容性

- 存量脚本零变化：不带 `:` 的 `<效果>` 走原分支。
- 唯一的解析面变化：以前 `[人物]<xx:yy>:文本` 会报 `UnableDial`，现在会被当成「带目标的效果」，
  目标名非法时报 `ParErrDial`。两者都是报错，不影响任何能跑通的脚本。

### 验证

- `core/{Regexs,ScriptParser,GUI_Snippets,Motion}.py` 通过 `py_compile`。
- 用 `toy/` 工程跑 `RplGenLog.execute()`，在 `MotionMethod.__init__` 上打桩，记录每个小节**实际构造出**的
  立绘/气泡切换效果（顺序固定为「先立绘、后气泡」）：

  | 场景 | 行内写法 | 默认值 | 立绘 | 气泡 |
  |---|---|---|---|---|
  | A | `<am:black=10>` | am=`replace=0` bb=`replace=0` | `black=10` | `replace=0` |
  | B | `<am:replace>` | am=`cross=10` | `replace=10` | `replace=0` |
  | C | `<black=10>`（无目标） | am=bb=`replace=0` | `black=10` | `black=10` |
  | D | `<black=10>` + `inline_method_apply=animation` | — | `black=10` | `replace=0` |
  | E | `<bb:black=10>` + `inline_method_apply=animation` | — | `replace=0` | `black=10` |
  | F | `<ab:black=10>` | — | `black=10` | `black=10` |

  A 场景另外确认了 `Am1_a` 时间轴是 0→100→0 的淡入淡出、而 `Bb_a` 全程恒为 100。
- **未实机验证**：GUI 补全部分需要图形界面，只做了语法与字典完整性检查（`RGLSnippets.Snippets` 两种语言都含 `ab_target`）。

### 顺带澄清（实测结论）

- 「设置了 `<set:am_method_default>` 之后，行内效果就无法替换立绘」**不成立**：场景 B 里行内
  `<am:replace>` 确实覆盖了默认的 `cross=10`（旧代码里行内就优先于默认值）。
- 真正**不受行内效果影响**的是**常驻立绘** `AmS`：对话行的 `<>` 只驱动 `Am1`–`Am3` 和 `Bb`；
  `AmS` 由 `<animation>` 放置行决定（该行没写效果时才回落到 `am_method_default`）。
  如果角色表走的是常驻立绘，现象就会像「行内效果改不动立绘」。要改常驻立绘的切换效果，
  得写在那条 `<animation>` 行上，或调 `<set:am_method_default>`。

## 1. 路径规范化、`MediaDef` 深复制、CLI 输出方式

**日期**：2026-11-02　**commit**：`0876e24`

### 动机

1. 在 Windows 下用 `@` 相对路径、自定义输出目录时路径拼接会错：`Mediapath` 末尾缺 `/` 时会拼成
   `目录名文件名`；外部传入的 `\` 与内部的 `/` 混用。
2. `MediaDef` 从工程文件（以 dict 载入）时 `media_path` 丢成了程序目录，`@` 路径全部指向错误位置。
3. `MediaDef.copy()` 不复制 `media_path`，深复制后退回程序目录。
4. `ChatWindow` 的 `sub_icon` 缺项/为空时抛 `IndexError`。
5. `main.py` 读取 `.rgpj` 时键名笔误（`medef`）、引用了不存在的 `self.json_input`，且只能预览、不能直接导出。

### 改动点

**`core/FilePaths.py`**

- 新增 `Filepath.normalize_dir(path)`：分隔符统一为 `/` 且保证以 `/` 结尾。
- 新增 `Filepath.set_media_path(path)`：设置 `Mediapath` 的规范入口。
- `Filepath.__init__`：`None` 输入抛 `MediaError('FileNFound')`；`\` → `/`；`@` 前缀拼接只拼一个 `/`。
- `Filepath.upper()`：空串直接返回空串（原来 `_str[0]` 会 `IndexError`）。
- `Filepath.relative()`：两侧都先 `normalize_dir`；空路径不参与 `startswith` 判断（否则 `''` 会前缀匹配一切）。

**`core/ScriptParser.py`**

- `MediaDef.__init__`：`dict_input` 时 `media_path` 取当前 `Filepath.Mediapath`（即工程目录），并统一
  `normalize_dir`。
- 新增 `MediaDef.copy()`：复制后保留 `media_path`。

**`core/Medias.py`**

- `RichText`：`sub_icon` 缺项或值为 `None`/`''`/`'None'` 时用空白图占位，而不是 `IndexError`。

**`core/GUI_FileManager.py`**

- 两处 `Filepath.Mediapath = ...` 改为 `Filepath.set_media_path(...)`（toy 工程与 `.rgpj` 载入）。

**`main.py`**

- `--Json` 分支：`Script(json_input=self.json_path)`（原来用了不存在的 `self.json_input`）；
  `medef` → `mediadef`；`rplgenlog` → `logfile[log_key]`，支持一份工程多份剧本，
  可用 `--LogFile <剧本名>` 选择，缺省取第一份；载入时 `Filepath.set_media_path(工程目录)`。
- 输出目录：未指定时缺省为工程目录下 `output/`，并统一 `normalize_dir`。
- 新增 `--ExportVideo` / `--ExportXML` 分支，真正调用 `ExportVideo` / `ExportXML`；
  `PreviewDisplay` 改为 `.main()` 并回传退出码。

### 兼容性

- `@` 相对路径在 Windows 下行为变正确；`Mediapath` 不带结尾 `/` 的旧工程也能正常拼接。
- CLI 新增两个 flag，原有参数不变。
